## 1. Experiment Update - 02/10/2026

I tested whether computing gradient norms for smaller parts of the network helps the detector. I compared a single backbone norm with stage, module, and parameter-tensor norms, and used SHAP to look at which features the detector relies on.

The finer norms give better ROC-AUC, including on the later task. The threshold results are less encouraging: the detector still flags too many clean samples in some runs, which causes a high false-positive rate when deciding whether a whole dataset is poisoned.

Section 8 reports the unsupervised checks on seeds 1 and 2.

### 2.3 Gradient Granularity

For an image $x$ with class label $y$, I compute the cross-entropy loss $L(x,y)=-\log p_y(x)$, then its gradient $g(x)=\nabla_{\theta_b}L(x,y)$ with respect to the backbone parameters. The model stays in evaluation mode, and no parameters are updated. Classification-head parameters are excluded from the gradient features, although the head still affects the loss and the gradient propagated to the backbone.

| Representation | Gradient Features | Definition |
| -------------- | ----------------: | ---------- |
| Global | 1 | One L2 norm over the backbone gradient |
| Stage | 5 | Separate norms for stem and layer1--4 |
| Module / Layer | 40 | One norm per named module, pooling its parameters |
| Parameter tensor | 80 | One norm per named weight or bias tensor |

Here, a parameter-tensor norm means one norm for a complete weight or bias tensor. For example, `conv1.weight` and `conv1.bias` give two features. I did not compute a separate feature for every scalar weight gradient.

All four representations measure gradient magnitude, not the size of the model weights. The global feature is $\sqrt{\sum_j g_j^2}$. A stage or module feature uses the same calculation over just that part of the network; a parameter-tensor feature uses the entries of one tensor. This lets the detector see where the gradient is concentrated, rather than only its total size. A module norm combines the squared weight and bias gradient norms before taking the square root.

### 2.4 Additional Features

I ran each gradient representation on its own, then repeated the comparison with five additional features, called "context" in the tables:

| Feature | Calculation | Definition |
| ------- | ----------- | ----------------- |
| Predictive entropy (`entropy`) | $H(x)=-\sum_k p_k(x)\log p_k(x)$ | How spread out the class-probability distribution is. Higher entropy means a less concentrated prediction. |
| Confidence (`confidence`) | $\max_k p_k(x)$ | The probability assigned to the model's preferred class, whether or not that class is correct. |
| True-class probability (`true_class_probability`) | $p_y(x)$ | The probability assigned to the image's actual class. Unlike confidence, this requires the true class label. |
| Prediction margin (`margin`) | $p_{(1)}(x)-p_{(2)}(x)$ | The gap between the largest and second-largest class probabilities. A small gap means the top two predictions are close. |
| Activation norm (`activation_norm_l2`) | $\|h(x)\|_2$, where $h(x)$ is the input to the incoming classification head | The magnitude of the backbone's final representation. This is one summary value, not the full activation vector. |

Here, $p(x)$ is the softmax output of the incoming head. I initialise this head with a fixed seed and leave it untrained during extraction. Entropy and confidence are therefore descriptors of the frozen model's response, not measures of the accuracy of a trained incoming-task classifier. I capture $h(x)$ immediately before the classification head with a forward hook.

This gives 1/5/40/80 features without context and 6/10/45/85 with context. I left out loss and historical-gradient cosine features in this experiment to keep the comparison focused on gradient granularity.

The gradients in this experiment use the true image-class labels. Only the target clean/poison labels are excluded from fitting and calibration; this is not a fully label-free method. I also kept the classifier settings fixed rather than tuning each feature set separately. Since the number of features changes, the models do not have the same number of coefficients.

### 2.5 Supervised Feature Sets Used in the Earlier Experiments

For reference, the earlier supervised experiments used the following combinations. These are separate from the eight granularity models evaluated below.

| Feature Set | Dimensions | Included Features |
| ----------- | ---------: | ----------------- |
| Baseline | 3 | Loss, global backbone gradient norm, and cosine similarity with the combined historical gradient direction |
| Extended | 16 | The three baseline features, three task-wise cosine statistics, five stage norms, and the five context features above |
| Portable | 10 | Five stage norms and the five context features |
| Shape | 5 | The five stage norms divided by their per-image L2 norm |

The extra features in this table are calculated as follows:

| Feature | Calculation and Meaning |
| ------- | ----------------------- |
| Loss (`loss`) | Cross-entropy $L(x,y)=-\log p_y(x)$. It measures how poorly the frozen model predicts the supplied image class. |
| Historical gradient cosine (`grad_cosine_past`) | Cosine similarity between the current backbone gradient and a combined historical reference direction. It describes directional agreement, rather than gradient magnitude. A negative value is not by itself evidence of poisoning. |
| Task-wise cosine statistics (`grad_cosine_task_min`, `grad_cosine_task_max`, `grad_cosine_task_mean`) | Compare the same current gradient with each historical task's reference direction, then retain the minimum, maximum, and mean similarities. These describe the range of agreement with previous tasks. |
| Normalised stage norms (`grad_shape_stage_*`) | Divide each stage norm by the L2 norm of the five stage values. This retains their relative sizes while removing the overall gradient magnitude. |

To build a historical direction, I first average the sample gradients from that task's inverted images and normalise the result. For the combined direction, I average these unit task directions and normalise again, so a task with a large raw gradient does not dominate the reference. The task-wise features use one current-sample gradient and several historical reference directions, not several gradients generated from the same current example.

The shape representation is $q_s(x)=G_s(x)/\sqrt{\sum_r G_r(x)^2}$, where $G_s$ is a stage norm. It deliberately ignores a uniform increase in gradient magnitude. If all five norms are zero, the shape is undefined and the code reports this rather than treating the sample as normal.

For all these supervised models, feature scaling is fitted on source training data and then frozen. Image-class labels are used to extract the features; clean/poison labels are used separately to train the detector.

### 2.6 Features Used by the Unsupervised Methods

The unsupervised methods use a different set of features and do not train a clean/poison classifier. Section 8 reports the original MMD and Rank results for seeds 1 and 2. Local shape and shape-MMD are described here for context, but their results are not included in this report. None of these methods was rerun as part of the gradient-granularity experiment.

For incoming images, the unsupervised branch replaces the true class $y$ with the model's own prediction, $\hat y=\arg\max_k p_k(x)$. Its backbone gradient is therefore computed from $L(x,\hat y)$. Historical reference images and incoming images are measured using the same frozen defender and incoming head. Neither incoming class labels nor clean/poison labels are used by the detection rule. The method still assumes that the historical checkpoints and reference tasks are clean.

The original MMD and Rank methods use the same ten per-image descriptors:

| Descriptor | Dimensions | Definition |
| ---------- | ---------: | ---------------------------------- |
| Global gradient norm | 1 | Overall backbone gradient magnitude, computed using the predicted class as the cross-entropy target |
| Stage gradient norms | 5 | Predicted-target gradient magnitudes for stem and layer1--4 |
| Entropy | 1 | Spread of the frozen head's class probabilities; no true label is needed |
| Confidence | 1 | Largest predicted class probability |
| Margin | 1 | Difference between the two largest predicted probabilities |
| Activation norm | 1 | L2 norm of the backbone representation entering the classification head |

Loss, historical-gradient cosines, and true-class probability are not inputs to these two methods. In predicted-label mode, the probability of the selected pseudo-class would simply equal confidence, so it would add a duplicate feature. The 40 module norms and 80 parameter-tensor norms from the present supervised comparison are not used by these unsupervised methods either.

The methods differ in what they compare:

| Method | Features or Statistics Compared | Purpose |
| ------ | ------------------------------- | ------- |
| Original MMD | The joint distribution of the ten descriptors above, after historical-reference preprocessing and a random Fourier feature map | Test whether incoming descriptors differ from the historical reference distribution |
| Rank | Up to 45 pairwise Kendall tau-a values from the ten descriptors; degenerate pairs are excluded using historical references only | Compare how features vary together, with less sensitivity to changes in their marginal magnitudes |
| Local shape | The five normalised stage norms, using predicted-target gradients | Measure each image's distance to nearby historical gradient shapes, then count unusually distant images |
| Shape-MMD | The distribution of the same five normalised stage norms, compared separately with each historical task | Test for changes in relative stage-gradient magnitudes without using their overall scale |

For the original MMD, I apply `log1p` to the gradient and activation norms, then use a median-based centre and robust scale fitted only on a separate historical-reference subset. The entropy, confidence, and margin features are not log-transformed. Rank instead compares pairwise ordering relationships; local shape and shape-MMD use per-image normalisation.

These choices try to reduce sensitivity to differences between historical inverted images and incoming real images, but they also discard information. For example, an attack that only rescales every stage gradient could be invisible to the shape methods. Their outputs measure novelty or distributional disagreement, not a calibrated probability that a dataset is poisoned.

## 4. Results on Task 9 Without Recalibration

### 4.1 Sample-Level Performance

| Feature Set | ROC-AUC | Clean Sample FPR | Poison Sample TPR |
| ----------- | ------: | ---------------: | ----------------: |
| Global | 0.709152 | 0.00% | 2.70% |
| Stage | 0.975506 | 7.40% | 94.30% |
| Module | 0.997446 | 33.50% | 100.00% |
| Parameter tensor | 0.998420 | 11.80% | 100.00% |
| Global + context | 0.776148 | 0.50% | 4.20% |
| Stage + context | 0.974942 | 15.70% | 97.10% |
| Module + context | 0.997156 | 34.40% | 100.00% |
| Parameter tensor + context | 0.998128 | 9.30% | 100.00% |

Without context, moving from stage to parameter-tensor norms raises mean ROC-AUC from 0.975506 to 0.998420, a gain of 2.29 percentage points. It also detects more poisoned samples: TPR rises by 5.7 points. However, clean FPR rises by 4.4 points as well.

When both models include context, parameter-tensor norms improve ROC-AUC over stage norms by 2.32 points and reduce clean FPR from 15.7% to 9.3%.

The module-level model is a clear example of the gap between ranking and classification: its AUC is high, but more than a third of clean samples cross the threshold on average. At the other extreme, the global-norm models rarely flag clean samples, but miss almost all poisoned samples too.

### 4.2 Effect of Context Features

Adding context helps the parameter-tensor model's clean FPR, reducing it from 11.8% to 9.3%, with little change in AUC (0.998420 to 0.998128). It has the opposite effect for stage norms, where clean FPR rises from 7.4% to 15.7%.

Since I added all five features together, this comparison does not tell me whether uncertainty or activation features are responsible for the change.

## 5. Which Layers or Parameters Contribute Most?

I used the source training samples as the SHAP background and explained the source validation predictions. The attributions are on the logistic model's log-odds scale.

| Representation | Seed 3 | Seed 4 |
| -------------- | ------ | ------ |
| Stage: highest-ranked gradient feature | `layer1` | `layer1` |
| Module: highest-ranked gradient feature | `layer1.0.conv2` | `layer1.0.conv2` |
| Parameter tensor: first-ranked gradient feature | `layer1.0.conv1.weight` | `layer1.0.conv2.weight` |
| Parameter tensor: second-ranked gradient feature | `layer1.0.conv2.weight` | `layer1.0.conv1.weight` |

Adding context does not change these leading gradient features. The top two parameter tensors also keep the same order within each seed.

The most consistent result is the contribution from the first residual block of `layer1`, especially its two convolutional weight tensors. One possible explanation is that combining a whole stage into a single norm hides useful differences between its modules. The results are consistent with that explanation, but I have not tested it directly.

These rankings describe how the fitted detector uses the features. They do not show that these layers cause the attack effect, or that a detector using only these layers would work equally well. Correlation between features can also affect the attribution. Several deeper-layer features appear among the leading contributors, even though they are not first in this table.

### 7.2 Seed 4 Has High False Alerts

For parameter tensor + context:

| Metric | Seed 3 | Seed 4 |
| ------ | -----: | -----: |
| Source reserve-clean sample FPR | 6.2% | 4.9% |
| Target clean sample FPR | 6.2% | 12.4% |
| Sample score threshold | 0.002405 | 0.005668 |
| Dataset rejection count, at least | 20 | 17 |
| Target clean-dataset alert rate | 0.0% | 72.6% |

For seed 4, 49 of the 1,000 source reserve-clean images exceeded the sample threshold. The one-sided upper bound on the clean sample alert probability was about 6.43%. The resulting rule rejects a dataset if at least 17 of its 150 images are flagged.

On Task 9, however, 62 of the 500 clean test images are flagged: the sample FPR has risen to 12.4%. Sampling 150 images from this pool gives an expected 18.6 flagged images, already above the rejection count of 17. This helps explain why so many clean datasets are rejected. The 72.6% rate is measured from the simulations, rather than calculated from this expectation.

The count calibration assumes that clean samples have the same alarm probability in the calibration and incoming data. The observed rates differ substantially here. Both the task and the model checkpoint change between source and target, which could change the feature distributions; I have not yet isolated which features account for the increase. The logistic scores should therefore not be read as calibrated probabilities of poisoning in a new task.

## 8. Unsupervised Results

### 8.1 Evaluation Setup

I compared Rank with the original MMD on Task 9, using historical inversion samples as the reference. Neither method had access to a known-clean subset of Task 9 or to the incoming class labels. I used clean/poison labels only to construct the test datasets and measure performance, not to fit or calibrate either method.

| Setting | Value |
| ------- | ----- |
| Experiment seeds | 1 and 2 |
| Methods evaluated | Fixed Rank method, with original MMD as the baseline |
| Reference data | Historical inversion samples from Tasks 0--8 |
| Incoming data | Task 9; predicted-class feature extraction |
| Dataset size | 150 distinct original images per simulated dataset |
| Simulations | 100 datasets per modification rate and perturbation type, for each seed |
| Rank test level | 0.05 |
| Rank bootstrap draws | 499 |

Rank compares the relationships between features in the incoming dataset with those in each historical task. It flags the dataset only if every historical comparison rejects a match: the largest per-task p-value must fall below the test level. I kept the settings unchanged for both seeds and fitted each reference model using that seed's own historical inversions.

All rates below are for whole datasets, not individual images. Each seed had a pool of 500 test originals. I sampled 150 distinct originals for each dataset, so there were no repeats within a dataset, but images were reused across datasets. The simulations are therefore not independent task experiments. Also, an alert means that the dataset differs from the historical reference, not necessarily that it is poisoned.

### 8.2 Clean and Poisoned Datasets

The original MMD flagged every dataset in both seeds, including the clean and random-control datasets. Rank gave fewer false alerts, but still rejected 21 of 100 clean datasets in seed 1 and 17 of 100 in seed 2. This is well above the nominal 5% test level. Both methods saw the same simulated datasets, and I did not adjust their thresholds using the test results.

| Actual Poisoned Fraction | Rank: Seed 1 | Rank: Seed 2 | Mean |
| ----------------------- | -----------: | -----------: | ---: |
| 0% (clean) | 21% | 17% | 19.0% |
| 1.33% | 12% | 14% | 13.0% |
| 5.33% | 18% | 16% | 17.0% |
| 10% | 17% | 21% | 19.0% |
| 25.33% | 56% | 98% | 77.0% |
| 50% | 52% | 100% | 76.0% |
| 100% | 67% | 100% | 83.5% |

At 10% poisoning or below, the mean alert rate was no higher than the clean-data rate. I do not see useful detection at these fractions. It detected more at 25.33% and above, but the two seeds differed considerably: even with every image poisoned, it detected 67% of datasets in seed 1 and 100% in seed 2.

Adding more poisoned images did not always increase detection. In seed 1, the rate fell from 56% at 25.33% poisoning to 52% at 50%. Rank measures feature relationships rather than counting poisoned samples, so a steadily increasing response is not guaranteed. Sampling variation may also contribute; I have not separated these effects.

It therefore does not reliably distinguish poisoning from random perturbations across the tested fractions.

### 8.4 Remaining Problems

Rank improves on the original MMD in these runs, but the two main problems remain: too many clean datasets are rejected, and low levels of poisoning are missed.

The method assumes that a clean incoming dataset will be compatible with at least one historical task in the statistics being tested. The clean-data results suggest that this assumption does not hold reliably for the inversion references. I have not isolated whether the mismatch comes mainly from inversion quality, task differences, or another source. Setting the test level to 5% has not kept the observed false-positive rate near 5%.

This comparison covers only Rank and the original MMD. I have not yet tested the finer parameter-tensor features from the supervised experiment in the unsupervised detector.


## 9. Summary and Next Step

The finer gradient norms helped in both seeds. Parameter-tensor norms reached a mean target ROC-AUC of 0.998420, compared with 0.975506 for stage norms. SHAP also gave a consistent result: the detector relies strongly on the convolutional weight gradients in the first block of `layer1`.

What remains unresolved is the decision threshold. Even with good ranking, the source threshold can flag too many clean target samples, and the dataset-level count rule magnifies this problem. Random perturbations also trigger frequent alerts. I would therefore describe this as an improvement in the features, rather than a solution to cross-task dataset detection.

The supervised comparison covers two previously examined seeds and one task pair. I cannot draw a statistical-significance or unseen-attack generalization claim from it. I have also not tested whether filtering the flagged samples improves subsequent continual-learning accuracy.

For the unsupervised detector, Rank detects many heavily poisoned datasets and gives fewer false alerts than the original MMD. It still rejects too many clean datasets and misses low-fraction poisoning, so I would not consider this part solved.
